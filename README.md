# German AI Text Detector

[![tests](https://github.com/HassanHijaze/german-ai-text-detector-from-scratch/actions/workflows/tests.yml/badge.svg)](https://github.com/HassanHijaze/german-ai-text-detector-from-scratch/actions/workflows/tests.yml)

Detects whether a German text is **human-written**, **AI-generated**, or **AI-assisted** (human text rewritten by an AI).

The best fine-tuned transformers get about 97 of 100 test texts right, while a general-purpose LLM simply asked to judge the text (Luna 6) gets only 56.

## Results

All models were evaluated on the same **held-out test set (2,737 texts)**. The supervised models were also tested on **869 out-of-distribution (OOD) texts** whose human texts come from domains never seen in training (Wikipedia, Wikinews, Wikivoyage, Wikibooks). The OOD AI texts were produced by the same four LLMs, so robustness to new LLMs is not tested.

| Model | Test accuracy | Macro-F1 | OOD accuracy | Human texts wrongly flagged |
|---|---:|---:|---:|---:|
| GeLECTRA-large | **96.89%** | **96.91%** | 96.32% | 4.70% |
| mmBERT-base | 96.64% | 96.65% | **96.55%** | 5.58% |
| mmBERT-small | 95.94% | 95.95% | 81.13% | 6.24% |
| TF-IDF + Logistic Regression | 91.23% | 91.22% | 79.40% | 8.53% |
| XLM-RoBERTa base | 91.09% | 91.03% | 91.83% | 21.66% |
| DistilBERT German | 90.83% | 90.82% | 89.41% | 19.91% |
| Luna 6 (GPT-6 Luna) | 55.64% | 50.83% | — | 1.42%¹ |

**Human texts wrongly flagged:** share of human-written test texts classified as AI-generated or AI-assisted.

¹ Low only because Luna 6 rarely predicts AI at all; it misses most AI texts.

The fine-tuned transformers’ probabilities are calibrated with temperature scaling (fitted on the validation set), which makes their confidence more realistic than the raw model outputs.

**Recommended model: mmBERT-base**, for its robustness on unseen human-text domains. The web app uses it.

## What we found

1. **The two best models are equally good.** GeLECTRA-large and mmBERT-base each get about 97 of 100 test texts right. GeLECTRA-large is slightly ahead on the test set and mmBERT-base on kinds of text it never saw in training, but each model was trained only once and the gap is just a few texts.
2. **A good test score doesn't mean the model handles new kinds of text.** mmBERT-small gets 95.9% of the test texts right, but only 81.1% of texts from domains it never saw in training.
3. **Short texts are hard.** Every trained model makes the most mistakes on texts of 70 words or fewer.
4. **Text that an AI only polished is harder to catch than text an AI wrote from scratch**, because it keeps the human author's ideas and structure.
5. **Texts from some AI models are harder to catch.** Every fine-tuned transformer misses texts from DeepSeek V4 Flash most often. But DeepSeek was also prompted differently (“topics” instead of “source_based”: it saw only 3 topics, not the human text) and its texts come mostly from peDOCS, so the effect can't be attributed to the generator alone.
6. **A confident answer can still be wrong.** When the models make a mistake, they are usually still more than 90% sure of their answer (before calibration).
7. **What the model notices:** humans abbreviate and use plain connectors, while AI spells words out and writes more formally. For example, “bzw.” appears in 25% of human texts but only 0.3% of AI-generated ones, and when AI polishes a human text, “aber” usually becomes “jedoch” (in 80% of cases). AI-generated texts also share favourite words: “zugleich” appears in 61% of them, but only 10% of human texts. (From the TF-IDF model’s strongest features, checked on the full dataset.)

## Quick start

### Try the detector (web app)

Runs locally with Docker. No GPU needed.

```bash
git clone https://github.com/HassanHijaze/german-ai-text-detector-from-scratch.git
cd german-ai-text-detector-from-scratch/11_deployment
docker build -t german-ai-text-detector .
docker run -p 7860:7860 german-ai-text-detector
```

Open **http://localhost:7860**, paste a German text, and click **Detect**. Details: [11 · Deployment](./11_deployment/).

### Models on Hugging Face

All trained models are available on [Hugging Face](https://huggingface.co/HassanHijazi). See [Models](#models) for the full list.

## Dataset

Most detectors only separate "human" from "AI". This project adds a third class for **AI-assisted** writing, because polished human text is hard to tell apart from both human and AI writing.

**30,629 German academic texts**, balanced across three classes:

| Class | Texts | How it was made |
|---|---:|---|
| Human | 10,227 | Openly licensed academic documents from **SSOAR, peDOCS and Refubium**, published before generative AI was widespread |
| AI-generated | 10,203 | A new text on the same topic, written from scratch by an LLM |
| AI-assisted | 10,199 | The human text, rewritten and polished by an LLM while keeping its meaning and structure |

AI texts were generated with **GPT-5.6 Luna, GPT-6 Luna, Gemini 3.8 Flash and DeepSeek V4 Flash**.

| Split | Texts |
|---|---:|
| Train | 24,986 |
| Validation | 2,906 |
| Test | 2,737 |

The data was split **by document**, so texts from the same source document never appear in two splits.

**OOD set:** 869 texts (290 human, 289 AI-generated, 290 AI-assisted). The human texts come from German Wikipedia, Wikinews, Wikivoyage and Wikibooks, which are encyclopedic, news, travel and instructional writing not present in training.

### Running the stages

```bash
git clone https://github.com/HassanHijaze/german-ai-text-detector-from-scratch.git
cd german-ai-text-detector-from-scratch
pip install -r requirements.txt
```

Copy `.env.example` to `.env` and add the API keys needed for the stages you want to run (AI text generation and the zero-shot baseline). The dataset is private, so stages that load it need access permission. The trained models are public.

## Running the tests

```bash
pip install -r requirements-dev.txt
pytest                                    # all tests except behavioral
pytest -m "not slow and not behavioral"   # quick run, skips the training test
pytest -m behavioral                      # behavioral tests (MFT, INV, DIR) and the parity test on the real model
```

The behavioral and parity tests use the real mmBERT-base, downloaded once from Hugging Face (~1.2 GB). All tests run automatically on GitHub Actions for every push.

## Limitations

- **Domain:** trained on German academic texts (mainly social sciences and education). Other kinds of text may be classified less reliably.
- **Generators:** AI texts come from four LLMs. Newer or different models may be harder to detect.
- **AI-assisted** here means a full rewrite of a human text by an AI. Other forms of AI help (e.g. editing single sentences) were not studied.
- **Length:** the models and the evaluation use only the first 512 tokens of a text (the web app analyses the full text in overlapping windows), and texts under 70 words are much less reliable.
- **Not proof:** the output is a probabilistic estimate. It must not be used on its own to accuse, grade or make other high-stakes decisions about people.
- **Style:** because the models rely partly on style markers (e.g. abbreviations and informal connectors for human texts, formal wording for AI texts), a human who writes very formally may be classified as AI more often.
